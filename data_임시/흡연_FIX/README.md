# 흡연 회귀 픽스처 (S12) — 2026-08-03 재고정

**LLM 변동과 코드 변경을 분리하기 위한 고정본.**
감리(STEP1)는 같은 입력에도 다르게 답한다 — `seed_weight` 0.7↔0.8, HITL 대기 4건↔3건,
`filter_by_code_prefix` op 유무. 그래서 *"코드를 바꿨더니 값이 변했다"* 와
*"LLM 이 다르게 답했다"* 를 구분할 수 없었다. 이 폴더가 그 경계를 만든다.

```
python check_fixture.py 흡연             # 대조 (읽기 전용)
python check_fixture.py 흡연 --restore   # 고정본 reviewed.json 을 step1_output 에 되돌림
python make_fixture.py  흡연             # 기준선 이동 — dry-run
python make_fixture.py  흡연 --write     # 실제 고정
```

**대조기와 갱신기는 분리돼 있다.** `check_fixture.py` 에 `--capture` 를 달지 않은 이유는,
확인용 도구가 자기 기준을 갈아치울 수 있으면 오타 한 번에 회귀가 기준으로 승격되고
그 뒤로는 그 회귀를 잡을 방법이 사라지기 때문이다.

---

## 구성

| | 내용 |
|---|---|
| `reviewed.json` | **고정된 감리 확정본.** LLM 변동의 유일한 원천 — 이것만 묶으면 STEP2~4 는 결정론이다 |
| `기준값.json` | 위 입력으로 STEP2~4 를 돌렸을 때 나와야 하는 값 46항목 + `reviewed_sha256` |
| `산출물/` | 당시 실제 산출물 사본 (clean_report · weight_set · report · topN_min) |
| `*.bak` | **직전 기준선.** `make_fixture.py` 가 실제로 교체할 때만 남긴다 |

`data/` 는 복사하지 않는다 — 537 MB 이고 원본은 어차피 안 바뀐다.
바뀌는 것은 **감리 결과**뿐이라 그것만 고정한다.

> 🔴 `check_fixture.py` 는 `산출물/` 을 **읽지 않는다.** 기준값 46항목만 본다.
> 그래서 사본 갱신을 빠뜨려도 대조는 46/46 으로 통과하고, 사람이 이 폴더를 열어
> **다른 실행의 값을 기준으로 착각한다.** 실제로 2026-08-03 그 상태가 됐다.
> 이제 `make_fixture.py` 가 사본을 함께 교체하고, 낡았으면 dry-run 에서 알린다.

## 이전 고정본(2026-08-03 오전)과 무엇이 달라졌나

**세 갈래가 겹쳤다. 하나로 뭉뚱그리면 진단이 거짓말이 된다.**

| 갈래 | 내용 |
|---|---|
| **코드 수정 ①** | 크로스워크 연결(`config.ADMIN_CROSSWALK_PATH` 신설). `04` 지역코드가 `unknown`(검증 불가) → `ambiguous` + 표본판정 행자부 2/2 로 `auto_confirmed`. `code_prefix_unverified` 플래그 1건 → 0건 |
| **코드 수정 ②** | `value_dist`(프로파일에 값 분포 전체) + 운영상태 프롬프트 규칙 → `05` 에 `운영현황 [정상,재개]` 필터. **173행 → 82행**(폐지·휴지 91곳 제외) |
| **LLM 변동** | `04` weight 0.8→0.7 · `11` 배제반경 null→30m · `08` 에 시군구 필터·trim 추가 · `03` whitelist 문자열 변경 |
| **실행 조건** | `--spacing 20`. 후보점 143,623 → 66,915 의 주된 원인이며 **회귀가 아니다** |

> 코드 수정 ②의 배경: `sample_rows` 는 **앞 2행**뿐이다. 어린이집 `운영현황` 은
> 9,483행 중 정상 3,835 / 폐지 5,504 / 재개 75 / 휴지 66 인데 앞 2행이 둘 다 '정상'이고
> `재개` 는 30번째 행에 처음 나온다. 감리 AI 가 볼 수 없으니 필터를 못 냈고,
> **폐지 어린이집까지 배제 대상**이 됐다. 값 분포를 코드가 조달하게 해서 고쳤다(원칙 3).

### union 이 줄어든 이유 — 실측 규명됨 (2026-08-03)

`11` 이 null→30m 로 늘었는데 총합은 1.1358→1.1107 로 줄어 앞뒤가 안 맞아 보였다.
`check_exclusion_state.py 흡연` 결과 두 힘이 반대로 걸린 것이었다.

| | 기존 | S9 |
|---|---|---|
| 01 금연구역 (90) | 0.0245 | 0.6325 · 필지 47→113 |
| 05 어린이집 (82) | 0.2224 | 0.2224 |
| 06 지하철역 (17) | 0.0053 | 0.0053 |
| 07 버스정류소 (314) | 0.0975 | 0.0975 |
| 11 어린이보호구역 (31) | 0.0875 | 0.4345 · 필지 12→34 |
| **union** | **0.4157** | **1.1107** (×2.67) |

- `05` 173→82행 → 약 0.44 → 0.2224 (**-0.22**)
- `11` 반경 부여 → 0.1685 → 0.4345 (**+0.27**)
- 그런데 `11` 증가분은 **대부분 `01` 과 겹친다** — 어린이보호구역은 학교 주변이고
  `01` 도 학교를 포함해 둘 다 같은 `학` 지목 필지로 확장한다.
  겹침 0.208 → 0.2815. `11` 의 한계 기여가 작아 `05` 감소가 그대로 드러났다.

`05` 감소는 **회귀가 아니라 수정**이다. 이전 0.44 km² 에는 **폐지 어린이집 91곳**이
들어 있었다 — 없는 시설 주변을 배제해 후보를 부당하게 깎고 있었다.

## 갱신 규칙

**자동 덮어쓰기 금지.** 픽스처를 바꾸는 것은 *"기준선을 옮긴다"* 는 선언이다.
`make_fixture.py` 가 강제하는 것:

1. `weight_set.inputs` 의 sha 가 현재 `reviewed.json`·`clean_report.json` 과 **일치**해야 한다
   (STEP3 뒤에 STEP1/2 를 다시 돌렸다면 여기서 멈춘다 — 서로 다른 실행이 한 기준으로 굳는 것을 막는다)
2. 산출물에 없는 수기값(`--union`·`--union-nsl`·`--spacing`·`--cli`)은 **이월하지 않는다.**
   인자로 안 주면 멈춘다. 조용히 이월하면 낡은 수치가 기준에 남는다
3. `기준값.json`·`reviewed.json`·`산출물/` 을 **함께** 교체한다

사람이 할 것: **왜 옮기는지 작업일지에 남긴다.** 위 "무엇이 달라졌나" 처럼 갈래를 나눠서.
